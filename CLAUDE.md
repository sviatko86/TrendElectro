# TRENDELECTRO — правила для Claude

Живий інтернет-магазин https://trendelectro.com.ua. Від нього залежать репутація і гроші клієнтів.
**Головне правило: зміни ніколи не повинні ламати сайт.**

## Як влаштовано
- Сайт: GitHub Pages з гілки `main` (кожен push одразу стає живим сайтом).
- Файли: `index.html`, `app.js`, `app.css`, `admin.html`, `sw.js`, `config.js`, `seo.js`.
- База: Supabase (проєкт `indkdtiofjahcshdxlcg`). У `config.js` лише публічний ключ (publishable).
- Бот `.github/workflows/seo.yml` щоночі сам оновлює `p/`, `c/`, `img/`, `poradu/`, `feed/`, `sitemap.xml`. Ці папки вручну не редагувати.

## Перед кожним push (обов'язково)
1. `node tools/check.js` має закінчитись словами «Усе гаразд». Інакше НЕ публікувати.
2. Змінено `app.js` або `app.css`: підняти `?v=` в `index.html` і версію кешу `te-shell-N` у `sw.js`.
3. Новий код отримує унікальні назви (функції, змінні, CSS-класи, id). Перед додаванням перевірити, що такої назви ще немає.
4. Після push перевірити, що GitHub Action «Перевірка сайту» пройшов (зелений).
5. Робити маленькі окремі коміти, щоб будь-яку зміну можна було відкотити через `git revert`.

## Нові функції
- Кожна нова функція сайту вмикається і вимикається перемикачем в адмінці (`admin.html`). За замовчуванням стоїть так, як погодив власник.
- Спершу показати власникові, що зміниться, і робити тільки після його «так».

## База Supabase
- Перед будь-якою зміною живої бази показати власникові SQL і чекати «так».
- Перед видаленням або масовою зміною даних спершу зробити резервну копію (таблиця `*_backup_YYYYMMDD` або експорт), потім змінювати, потім перевірити результат запитом.
- Секретні ключі (`service_role`, `sb_secret_…`) ніколи не потрапляють у репозиторій. Їх місце лише в секретах Supabase або GitHub.

## Правила контенту
- Назва «Світ-Буд» / svit-bud ніде не з'являється на сайті (назви, описи, бренд, посилання на фото).
- Кабель, бухти, LED/NEON-стрічки, скоби, LED-модулі, батарейки продаються упаковками: ціна за упаковку, у картці лише «В упаковці».
- Решта бізнес-правил (ціни, націнки, картки) зберігається в налаштуваннях адмінки та в базі. Їх не змінювати без власника.
